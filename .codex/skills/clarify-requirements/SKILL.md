# clarify-requirements

**Input:** A requested change and any related GitHub issue or specification.

1. Read the relevant project context and inspect existing behavior. Search for a matching GitHub issue when access is available; report if that search could not be completed.
2. Describe the owner, affected roles, goal, non-goals and observable acceptance criteria. For a bug, include reproduction steps and expected versus actual behavior.
3. Ask about missing or conflicting requirements that affect scope or correctness. State reasonable assumptions for minor details.
4. Reuse the matching issue, or prepare issue text. Create or update the issue when authorized, then provide the requirements to `write-plan`.

**Done when:** The requirements are ready for human agreement, with an issue reference or ready-to-use issue text and any unresolved decisions clearly listed.
