# Shared domain model and repository interfaces

**Issue:** [#4](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/4) - Agree the shared domain model and repository interfaces
**Branch:** `feat/shared-domain-model`
**Status:** Initial models/interfaces, the conflicting-scalar read fix, obsolete workflow/model removals, the valid-answer count clarification and the narrowed deletion contracts are implemented locally. The removals/count changes were independently reviewed; they and the deletion contracts await human verification; the reviewed #6 transaction contract is published. Detection, lifecycle, provenance, remaining batch metadata, terminal-outcome, fixed-assignment, statistics, workspace-media and account-enforcement follow-ups remain unimplemented. The temporary scalar-read regression tests were removed at Whimsyturtle's request and should be restored with the later test work. The issue is co-owned by zheng-jj and Whimsyturtle; this plan records accepted scope alongside the remaining model cleanup.

## Result

`./gradlew check` passes. 12 model classes, 10 enums and 12 repository interfaces (57 method signatures) compile under `arbiter.model` and `arbiter.data`, with no SQL, no ORM annotations and no dependency on a database. `.gitignore` also needed anchoring: its `data/` pattern was matching `src/main/java/arbiter/data/` and would have excluded the package from the commit.

## Goal

Commit the model classes, enums and repository interfaces that both feature tracks code against, so the annotator and adjudicator work can proceed in parallel without constant merge conflicts.

## Non-goals

- Persistence: no SQL, no schema, no migrations. That is [#6](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/6).
- UI, services and any feature behaviour.
- Password hashing ([#7](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/7)).

## Decisions to confirm

The three the issue asks for, plus four that came up while drafting.

1. ***k* defaults to 2, and lives on `Split`.** Revised after review: it was first put on `Assignment`, but *k* describes the work rather than one annotator's link to it, and every annotator on a split sees the same items. The reviewer was right to move it.
2. **`BoundingBox` gets its own table**, not an inline blob on `Annotation`. [#36] needs per-box provenance, [#37] writes per-box records, and [#15]'s box list needs a stable order, so boxes carry an explicit `sequence`.
3. **A `SCALE` answer is stored as a whole number.** `Annotation.scaleValue` is an `Integer`; the range lives on `TaxonomySettings`, not `Project`. `Resolution.scaleValue` is a `Double` to retain fractional arithmetic means. The agreed v1 rule is recorded in the review decisions below and User Flows rule 10.
4. **`Flag` gets its own table** rather than three nullable columns on `Annotation`. [#35] lists flagged items filterable by reason, and [#36] shows current flags and dispositions, which are both natural queries against a flag table.
5. **Taxonomy kind lives with the project, not on `Label`.** [#29] sets the task type and taxonomy kind at creation and rejects impossible combinations; the scale range is a property of that taxonomy, and now lives in `TaxonomySettings`. Multi-select was dropped in review, so there are no multi-select bounds.
6. **Repositories beyond the seven named in the issue.** `ResolutionRepository` and `FlagRepository`, joined later by `SplitItemRepository` and `TaxonomySettingsRepository`. [#27], [#34], [#35] and [#36] all read and write these directly; without them those issues either add interfaces later, which is the drift this issue exists to prevent, or route through `ItemRepository`, which is worse.
7. **Keep `AccountStatus` for annotator deactivation.** `ACTIVE`/`DISABLED` support login checks and retained attribution under [#7](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/7)/[#31](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/31); the sole adjudicator remains ACTIVE. No email-verification status is needed.

## Open questions

- **ORM annotations.** `context/architecture.md` says model classes carry ORM mapping annotations, but this issue says to add them "as plain value objects". The draft follows the issue: plain POJOs, no ORMLite annotations, so the mapping is designed in [#6](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/6) alongside the schema instead of being guessed here. If that is wrong, the architecture line needs changing too.
- **Timestamps.** The draft uses `java.time.Instant`. ORMLite has no built-in `Instant` mapping, so [#6](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/6) either registers a persister or this switches to a type it maps natively.
- **`equals` / `hashCode`.** Not defined yet. Entities compare by identity today; say if value equality is wanted.
- **Immutability.** `Project.taskType`, `sourceType` and `outputFormat` are settable, not final, because ORMLite sets fields reflectively. Rule 4 is enforced in `arbiter.service`, per the architecture rule that every rule about the data lives there.

## Proposed changes

- `arbiter.model`: 12 classes (`Annotation`, `Assignment`, `BoundingBox`, `Flag`, `Item`, `Label`, `Project`, `Resolution`, `Split`, `SplitItem`, `TaxonomySettings`, `User`) and 10 enums (`AccountStatus`, `AssignmentStatus`, `FlagDisposition`, `FlagReason`, `OutputFormat`, `ResolutionMethod`, `Role`, `SourceType`, `TaskType`, `TaxonomyKind`).
- `arbiter.data`: 12 repository interfaces (57 signatures), signatures only.
- No `build.gradle` change.

## Review decisions

Whimsyturtle requested changes on the first revision. The decisions below are his, applied after rebasing on the docs branch; the original numbered list above is kept as the record of what was proposed.

- **Subpackages.** Both `arbiter.model` and `arbiter.data` are split by area - `user`, `project`, `annotation`, `resolution` - mirroring each other.
- **Dropped enum constants.** Earlier review removed `AccountStatus.PENDING`, `SourceType.MD`, `TaxonomyKind.MULTI`, `ResolutionMethod.GOLD`, and `FlagReason.DUPLICATE`/`OFF_TOPIC`/`INSTRUCTIONS_UNCLEAR`. `AssignmentStatus.RETURNED` was removed then restored to satisfy the requirements at that time. The later accepted forward-only decision superseded those return requirements, so the current cleanup removes RETURNED and `FlagDisposition.REPAIRED`.
- **Dropped fields.** `User.email` becomes `username`. `Label.name` and `Label.colour` go, leaving `key` plus `description`. `Annotation.timeSpentMillis` goes. `Flag.excluded` goes, because `Item.retired` already covers exclusion.
- **`TaxonomySettings`.** The scale bounds moved out of `Project` into their own class, so a project is not a bag of optional numbers that matter for one taxonomy kind only.
- **Mutual exclusion.** `Annotation` and `Resolution` may store a label or a scale value, and may store neither for drafts, detection or unresolved records. Their setters clear the other field when given a non-null value. Because reflective hydration bypasses those setters, both scalar getters reject a record with both fields populated without hiding or repairing the invalid state.
- **`Flag` records the disposition.** Earlier #35 required exclude/repair/keep, so the branch gained `FlagDisposition` and review time. The later forward-only decision defers repair and retains keep/exclude; the current adjudicator disposition/reviewer/time is separate from immutable reporter content. `Item.retired` still determines exclusion from active work/export.
- **Return metadata is removed.** `Assignment.returnedAt`, `returnedByUserId` and `returnReason` satisfied the earlier rework requirement. The accepted forward-only decision removes that workflow and the current cleanup deletes those fields/accessors.
- **One direction per relationship.** `Project` no longer holds a `TaxonomySettings` object, since `TaxonomySettings.projectId` already points back and two directions can disagree. `TaxonomySettingsRepository` was also missing, leaving one entity with no way to load or save it.
- **Scales stay in v1 with arithmetic-mean resolution.** On 21 September, Whimsyturtle chose to retain scales and defer tolerance and automatic scale-disagreement detection. `Resolution.scaleValue` remains a `Double` for fractional means. [#27](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/27) and [User Flows rule 10](../docs/UserFlows.md#3-rules-both-tracks-share) define the rule; this model PR does not implement the service.
- **Detection stays in v1 with selection of one complete submitted box set.** Whimsyturtle chose to retain annotator box editing and COCO export while simplifying adjudication: after *k* valid submitted annotations, select one annotator's complete set for that item. No automatic box matching, combining submissions or editing boxes during resolution. [#34](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/34) and [User Flows rule 16](../docs/UserFlows.md#3-rules-both-tracks-share) define the rule. **Model follow-up remains:** `Resolution` currently stores only a label or scale value; add a persistent relationship identifying the selected annotation for detection, retaining unselected submissions for provenance. This documentation decision does not implement that relationship or the service/export behaviour.
- **Freeze setup after assignment and seal completed projects.** [User Flows rules 3/6/9/13/14](../docs/UserFlows.md#3-rules-both-tracks-share) freeze corpus/taxonomy at the project's first assignment, lock each assigned split's definition and make COMPLETE seal all project data with no reopen or completed-project deletion. Completion may be confirmed with unfinished work, which is sealed as-is. Before completion, forward-only submissions, separate resolution and keep/exclude review continue; the later decision removes returns and repair. Exclusion retains membership/evidence. Never-assigned batches follow count-only creation rules; the later fixed-assignment decision prohibits unassignment entirely.
- **Lifecycle implementation follow-up.** Persist first-assignment evidence and enforce locks/sealing transactionally in services/persistence. Mutable POJOs and repository interfaces do not supply those guarantees. The deletion contracts now match these rules: no individual answer, assignment or single-membership delete remains, and label deletion is setup-only without cascading into answers. Account replacement is deferred by the later fixed-assignment decision; the accepted workspace-media boundary and source-integrity checks below still need enforcement.
- **Keep submitted evidence and the current decision.** The earlier current-only provenance decision remains, simplified by one-way submission: retain every annotator's immutable submitted answer or explicit report-only outcome, unselected evidence, current resolution/contributors or selected detection set/method/decider/time, and current flags/dispositions/review metadata. No withdrawn/replacement submissions, return metadata, answer revisions or historical timelines are required. COMPLETE seals unfinished drafts as drafts.
- **Provenance implementation follow-up.** The former requirement to keep an old submission beside a revised draft is superseded; a current draft becomes one immutable terminal submission. Agree the answer-versus-report-only representation and submission timestamp, preserve original authorship, and identify exact resolution contributors. No source implementation is added by this decision.
- **`Project.outputFormat` is fixed at creation too**, which the review questioned and the docs now state.
- **Repository naming.** Methods returning a collection are `list*`; `findAll()` became `listAll()`, and the same rule applied to every other collection-returning method.
- **Shared transaction boundary belongs to persistence.** [#6](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/6) now requires all repositories participating in one logical action to use the same transaction and roll the whole action back on failure. Write-through means the completed action is committed immediately, not that each intermediate repository call commits. #4 does not invent a transaction API before the persistence design is implemented.
- **`countByRole` was a real bug under the earlier multi-adjudicator policy.** It counted disabled accounts, so the last-adjudicator guard did not hold; the branch changed it to `countActiveByRole`. The accepted single-adjudicator rule below supersedes that guard. Review the method's remaining uses and remove the obsolete rationale during contract cleanup; counting active users alone does not enforce a fixed owner.
- **`Item.path` needs a narrower contract.** The current generic source-location comment must become workspace-relative (`media/...`) under the accepted import rule below. `contentHash` identifies the registered bytes; neither field is a relink/replacement escape hatch. Source validation belongs in the shared workspace resolver and services, not model getters.
- **Count-only work batches; defer training/validation/test partitioning.** Whimsyturtle chose automatic batches by items-per-batch count, using one defined seeded shuffle and stable input ordering. Persist the actual seed, requested batch size and generated membership/order, which remains authoritative on reopen. Identical inputs/count/seed reproduce an allocation; rebuilding past corpus states or deleted batches is outside v1. [#28](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/28) defines creation from available items and replacement of never-assigned batches, with no percentage sizing, manual picking/moving or stratification. [#37](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/37) retains CSV/JSON/COCO export with current provenance but defers training/validation/test subsets. The current cleanup removes the obsolete strategy field/type. **Implementation follow-up remains:** represent the requested batch size and update the seed/membership comments. No allocator, persistence or exporter behavior is implemented by this change.

- **Money tracking is deferred beyond v1.0.0.** The earlier [#2](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/2) vesting decision is historical and superseded for v1. Per-item reward configuration, pending/released earnings, the completed-assignment pay gate, the report-only pay question and the income CSV are outside the v1 contracts; [#20](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/20) and [#21](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/21) are deferred. The current cleanup removes `Split.itemReward` and the earnings-specific repository wording while preserving [#19](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/19)'s valid-annotation count.

- **Forward-only submission replaces review/rework.** Whimsyturtle accepted editable autosaved current drafts followed by explicit Submit & next, permanently locking the item and advancing. No Back, review pass, arbitrary jump, skip-and-return, final batch-submit, return/resubmission or direct adjudicator repair. Assignment SUBMITTED follows automatically when all non-retired requirements are handled, including after exclusion removes the final outstanding item. [#13](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/13), [#16](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/16) and [#17](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/17) own the queue/outcome contract. Keep bulk keep/exclude; it was not cut. The obsolete return/repair values and fields are now removed. **Implementation follow-up:** represent a terminal report without a valid answer, persist submitted time and resume position, and provide atomic/idempotent submission/advancement/completion. A cursor or a proven deterministic resume derivation is still needed; no skip history is required. The conflicting-scalar read defect is fixed; the other model gaps remain separate work.

- **No reassignment at all in v1.** Whimsyturtle chose fixed assignments from creation, even before any draft or submission: no unassign, selective deletion, transfer or replacement/takeover. Account deactivation retains ownership/work and consumes the existing place within fixed *k*; only genuinely unused places may be filled before COMPLETE. [#31](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/31), [#32](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/32) and [User Flows rule 19](../docs/UserFlows.md#3-rules-both-tracks-share) define the accepted scope. Normal progress/status updates and separately confirmed whole incomplete-project deletion remain. `AssignmentRepository.deleteById` is removed; assignments are deleted only with a whole incomplete project. **Implementation follow-up:** guard persisted `splitId`/`annotatorId`, duplicate split/annotator creation and total assignments up to *k* transactionally, counting disabled owners. No transfer state, replacement queue or history model is needed; this documentation update implements none of those guards.

- **Keep statistics with single-select label agreement.** Whimsyturtle rejected cutting session timing/activity charts and accepted label agreement only, with N/A for scales and detection. [#33](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/33) and [User Flows rule 20](../docs/UserFlows.md#3-rules-both-tracks-share) define an equal-item mean of matching annotator-pair fractions, using original valid submitted labels from fully answered non-retired items with *k* at least 2. Resolution success, majority size and scale averaging are not agreement measurements. Existing progress/session statistics and valid-annotation totals/activity charts remain [#18](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/18)/[#19](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/19). **Implementation follow-up:** provide the already-required immutable submission timestamp and repository aggregates for item-score sums/eligible counts, with no full edit-history log, stored agreement counter, scale tolerance or box-matching contract. No Java source or statistics implementation changes in this scope update.

- **Register source files in place inside workspace media.** Whimsyturtle rejected the copy-only proposal and accepted users placing images/text inside the shared workspace's `media/` folder before import. [#9](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/9), [#10](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/10), [#25](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/25) and [User Flows rule 21](../docs/UserFlows.md#3-rules-both-tracks-share) define relative locations, resolved containment and content validation. Remove optional copy/external-source/per-file relink contracts; no copy-mode field, relocation history or extra media entity is needed. Missing/corrupt/changed sources yield clear errors without changing existing evidence or fabricating answers; report-only submission remains before COMPLETE. Exact-byte restoration needs no database edit, and source files survive project deletion. **Implementation follow-up:** narrow path/hash comments and importer/resolver/valid-submission/export contracts, preventing traversal/link escapes and stale cached acceptance of changed media. The existing project seal remains an application rule, not a guarantee against file-system edits. This documentation change implements none of these guards.

- **One fixed adjudicator; direct annotator credentials.** Whimsyturtle accepted one first-run adjudicator per workspace, owner-created annotator accounts and direct replacement of annotator passwords ([#7](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/7), [#31](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/31), [#23](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/23), [User Flows rule 12](../docs/UserFlows.md#3-rules-both-tracks-share)). Remove self-signup, promotion/demotion, additional adjudicators, owner transfer/deactivation/deletion and one-time reset-code contracts. Email verification/reset are deferred beyond v1. Preserve role distinctions, annotator deactivation, IDs and decision attribution; resetting credentials never recreates/reactivates an account or changes its work. **Implementation follow-up:** atomic one-time bootstrap, immutable persisted roles/owner status, shared hashing and credential-only updates in services/persistence; mutable `User` setters and the current repository interface do not enforce these rules. No code/token/expiry entity is needed. Owner password recovery remains unresolved, with no new bypass or second-owner mechanism promised. No Java source changes in this scope update.

### Second review round

- **`Split` gained `SplitItem` and `seed`.** The reviewer spotted that a split had no way to record which items it held. Membership is now its own record; later accepted decisions limit creation to automatic count-based batches and replacement to never-assigned batches. Flag exclusion preserves those records. The later rule 7 clarification makes saved membership/order authoritative and bounds seed reproducibility to identical inputs/count/seed; the intermediate multi-strategy type has been removed.
- **`Label.active` was removed.** It made a new label look deleted, and it also contradicted rule 5, which permits deletion of unused setup labels. The later lifecycle decision prohibits label deletion after assignment and removes the annotation cascade.
- ***k* moved from `Assignment` to `Split`**, as above.
- **`TaxonomySettings` gained `id` and `projectId`**, without which ORMLite could not persist it at all.
- **`countValidSubmittedByAnnotator` serves annotation totals only.** Its contract counts valid submitted answers for non-retired items under [#19](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/19), excluding drafts and report-only outcomes. It does not drive [#18](https://github.com/CS3227-2610-MP2-Arbiter/CS3227-2610-MP2/issues/18) progress, where both terminal answer and report-only outcomes are handled and retirement removes outstanding work without inventing a submission. Per-project/day and agreement aggregates remain with #19 and #33.
